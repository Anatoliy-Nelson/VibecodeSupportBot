# LLM Wiki Pattern (Karpathy)

#llm #wiki #knowledge-management #pattern #karpathy

## 📋 Описание

Паттерн создания персональной базы знаний с использованием LLM, предложенный Андреем Карпаты. Вместо традиционного RAG (Retrieval-Augmented Generation), где информация извлекается из сырых документов при каждом запросе, LLM инкрементально строит и поддерживает постоянную wiki — структурированную, взаимосвязанную коллекцию markdown-файлов.

## 🎯 Ключевая идея

**Основная проблема RAG:** При каждом запросе LLM заново открывает знания с нуля. Нет накопления. Задайте тонкий вопрос, требующий синтеза из пяти документов — и LLM каждый раз вынужден искать и собирать фрагменты.

**Решение:** Wiki — это постоянный, компилируемый артефакт. Перекрёстные ссылки уже есть. Противоречия уже отмечены. Синтез уже отражает всё прочитанное. Wiki становится богаче с каждым источником и каждым вопросом.

> **Аналогия:** Obsidian — это IDE, LLM — программист, wiki — кодовая база.

## 🏗️ Архитектура

### Три слоя:

1. **Сырые источники** — коллекция исходных документов (статьи, статьи, изображения, данные). **Неизменяемы** — LLM только читает, никогда не модифицирует.
2. **Wiki** — директория markdown-файлов, созданных LLM. Резюме, страницы сущностей, концепций, сравнения, обзор, синтез. LLM полностью владеет этим слоем.
3. **Схема** — документ (`QWEN.md`), который указывает LLM как структурирована wiki, какие конвенции соблюдать и какие рабочие процессы выполнять. Ключевой конфигурационный файл.

## ⚙️ Операции

### Ingest (Поглощение)
- Добавляете новый источник в коллекцию
- LLM читает, обсуждает ключевые выводы, пишет резюме, обновляет index, обновляет страницы сущностей/концепций, добавляет запись в log
- Один источник может затронуть 10-15 страниц wiki

### Query (Запрос)
- Задаёте вопросы к wiki
- LLM ищет релевантные страницы, синтезирует ответ с цитатами
- Хорошие ответы можно сохранять обратно в wiki как новые страницы

### Lint (Проверка здоровья)
- Периодически просите LLM проверить wiki на:
  - Противоречия между страницами
  - Устаревшие утверждения
  - Сиротские страницы без входящих ссылок
  - Важные концепции без отдельных страниц
  - Отсутствующие перекрёстные ссылки

## 📑 Индексирование и логирование

### `index.md` — содержательный каталог
- Каталог всего в wiki — каждая страница со ссылкой, кратким резюме и метаданными
- Организован по категориям (сущности, концепции, источники)
- Обновляется при каждом поглощении
- Работает хорошо до ~100 источников, ~сотен страниц

### `log.md` — хронологическая запись
- Append-only журнал событий: поглощения, запросы, проверки
- Формат: `## [2026-04-02] ingest | Article Title`
- Можно парсить Unix-утилитами: `grep "^## \[" log.md | tail -5`

## 🛠️ Инструменты и советы

### Obsidian
- **Web Clipper** — расширение для сохранения веб-статей в markdown
- **Graph View** — визуализация связей wiki
- **Dataview** — запросы к YAML frontmatter
- **Marp** — markdown-презентации
- **Загрузка изображений** — сохранять локально для доступа LLM

### CLI инструменты
- **qmd** — локальный поиск по markdown (BM25 + vector + LLM re-ranking)
- Можно создать собственные инструменты помощи LLM

## 💡 Почему это работает

Утомительная часть ведения базы знаний — не чтение или мышление, а **бухгалтерия**: обновление перекрёстных ссылок, поддержание резюме в актуальном состоянии, отметка противоречий, поддержание согласованности.

**Люди** отказываются от wiki, потому что нагрузка на обслуживание растёт быстрее, чем ценность.

**LLM** не скучает, не забывает обновлять ссылки, может обработать 15 файлов за один проход. Стоимость обслуживания близка к нулю.

> **Роль человека:** курировать источники, направлять анализ, задавать хорошие вопросы, думать о смысле.
> **Роль LLM:** всё остальное.
