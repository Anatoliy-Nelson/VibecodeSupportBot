# QWEN — Персональная база знаний

## Роль
Ты — мой LLM wiki-агент. Твоя задача — помогать мне структурировать, сохранять и извлекать знания из этой базы.

## Принципы работы
- **Точность**: Информация должна быть проверенной и актуальной
- **Структура**: Логичная организация знаний с использованием ссылок `[[WikiLinks]]`
- **Контекст**: Каждая заметка должна быть понятна без дополнительного контекста
- **Связность**: Заметки связаны между собой через双向ные ссылки

## Конвенции
- Файлы в формате Markdown
- Именование файлов: `kebab-case.md`
-双向ные ссылки: `[[Название заметки]]`
- Теги для категоризации: `#тег`
- YAML frontmatter для метаданных (теги, дата создания, источник)

## Структура базы

### 📂 Директории

```
Vibecoding_Incubator/
├── QWEN.md              # Инструкции для LLM wiki-агента (этот файл)
├── index.md             # Главная навигационная страница (каталог wiki)
├── log.md               # Хронологический журнал изменений
├── Добро пожаловать.md  # Стартовая страница (можно удалить)
│
├── raw/                 # СЫРЫЕ ИСТОЧНИКИ (неизменяемые)
│   ├── assets/          # Изображения и медиа из источников
│   └── *.md             # Статьи, документы, заметки для обработки
│
└── wiki/                # LLM-ГЕНЕРИРОВАННЫЕ СТРАНИЦЫ
    ├── entities/        # Страницы сущностей (люди, организации, продукты)
    ├── concepts/        # Страницы концепций (паттерны, техники, идеи)
    ├── topics/          # Обзорные страницы по темам/разделам
    └── synthesis/       # Синтез, сравнения, аналитика, выводы
```

### 📋 Назначение директорий

**`raw/`** — Сырые источники
- Сюда вы добавляете статьи, документы, заметки
- **Неизменяемы** — LLM только читает, никогда не модифицирует
- Формат: `raw/название-статьи.md`
- Изображения из источников: `raw/assets/`

**`wiki/entities/`** — Сущности
- Люди, организации, продукты, конкретные объекты
- Пример: `wiki/entities/andrej-karpathy.md`

**`wiki/concepts/`** — Концепции
- Паттерны, техники, методы, идеи
- Пример: `wiki/concepts/llm-wiki-pattern.md`

**`wiki/topics/`** — Темы
- Обзорные страницы по широким темам
- Пример: `wiki/topics/knowledge-management.md`

**`wiki/synthesis/`** — Синтез
- Сравнения, аналитика, выводы, связи между концепциями
- Пример: `wiki/synthesis/rag-vs-wiki-comparison.md`

## Инструкции для агента

### При создании новой заметки:
1. Определить тип (entity/concept/topic/synthesis)
2. Создать файл в соответствующей папке `wiki/`
3. Добавить YAML frontmatter с тегами и датой
4. Добавить ссылку в [[index]]
5. Добавить запись в [[log]]
6. Обновить перекрёстные ссылки

### При поглощении источника из `raw/`:
1. Прочитать источник
2. Обсудить ключевые выводы с пользователем
3. Создать/обновить страницы в `wiki/` (может затронуть 10-15 файлов)
4. Обновить [[index]]
5. Добавить запись в [[log]]

### При запросе:
1. Поискать релевантные страницы в `wiki/`
2. Синтезировать ответ с цитатами
3. Если ответ ценный — предложить сохранить как новую страницу в `wiki/synthesis/`

### Периодическая проверка (Lint):
- Проверить на противоречия между страницами
- Найти устаревшие утверждения
- Найти сиротские страницы без входящих ссылок
- Предложить новые источники для исследования

## 🤖 Claude Memory Compiler Integration

### Автоматическая компиляция разговоров с AI

**Структура в корне проекта:**
```
project-root/
├── daily/                 # Ежедневные логи разговоров (auto)
├── knowledge/             # Скомпилированные знания (auto)
│   ├── index.md           # Мастер-каталог
│   ├── log.md             # Build log
│   ├── concepts/          # Атомарные знания
│   ├── connections/       # Перекрёстные связи
│   └── qa/                # Сохранённые ответы
├── hooks/                 # Claude Code hooks
│   ├── session-start.py   # Инжекция знаний в сессию
│   ├── session-end.py     # Разговор → daily log
│   └── pre-compact.py     # Страховка от потери контекста
├── scripts/               # CLI инструменты
│   ├── memory-compile.py  # Компилятор daily → knowledge
│   ├── memory-query.py    # Index-guided retrieval
│   ├── memory-lint.py     # 7 health checks
│   ├── memory-flush.py    # Извлечение памяти
│   ├── memory-config.py   # Конфигурация путей
│   └── memory-utils.py    # Общие утилиты
├── .claude/settings.json  # Hook конфигурация
├── AGENTS.md              # Схема компилятора
└── pyproject.toml         # Python зависимости
```

**Hooks (автоматически):**
- **SessionStart** — при начале сессии инжектирует knowledge index
- **SessionEnd** — при конце сессии сохраняет разговор в daily/
- **PreCompact** — перед авто-компактизацией сохраняет контекст
- **Авто-компиляция** — каждый день в 00:05 (настраивается в `scripts/flush.py`)

**Команды:**
```bash
uv run python scripts/memory-compile.py              # компиляция daily logs
uv run python scripts/memory-query.py "вопрос"       # запрос к базе
uv run python scripts/memory-lint.py --structural-only  # проверки
```

**Зависимости:** Установлены через `uv sync` (claude-agent-sdk, python-dotenv, tzdata)

### Git Hook (post-commit)
- **Скрипт:** `scripts/auto-log-to-wiki.ps1`
- **Hook:** `.git/hooks/post-commit`
- **Что делает:**
  - После каждого коммита анализирует изменения
  - Фильтрует технические изменения (log.md, .gitkeep, Vibecoding_Incubator/)
  - Определяет тип: feat, fix, refactor, docs, update
  - Добавляет запись в `log.md` с датой, автором, хешем коммита, списком файлов
- **Формат записи:**
  ```
  ### [2026-04-13] feat | Добавлена авторизация
  - **Автор:** Sithe
  - **Коммит:** "abc123..."
  - **Изменённые файлы:**
    - "M" "support-admin/src/auth.tsx"
    - "A" "supabase/functions/auth/index.ts"
  ```
- **Когда срабатывает:** Только при значимых изменениях (не технические файлы wiki)
- **Дедупликация:** Проверяет по хешу коммита, не добавляет дубликаты
